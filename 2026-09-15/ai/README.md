# ساخت Retrieval برای RAG با Chunking و Citation

## هدف یادگیری

در پایان می‌توانی متن‌ها را به Chunkهای هم‌پوشان تقسیم کنی، Chunkهای مرتبط با سؤال را رتبه‌بندی کنی و پاسخ را همراه با شناسهٔ منبع برای یک LLM آماده کنی.

## پیش‌نیاز

- Python 3.10 یا جدیدتر
- آشنایی مقدماتی با مفهوم RAG و Embedding
- برای نمونهٔ امروز هیچ Package یا API خارجی لازم نیست

## 1. RAG چه مسئله‌ای را حل می‌کند؟

مدل زبانی از دانش داخلی خود پاسخ می‌دهد، اما اطلاعات سازمانی یا جدید را الزاماً نمی‌داند. در RAG ابتدا بخش‌های مرتبط از اسناد بازیابی می‌شوند و سپس همراه سؤال به مدل داده می‌شوند.

```text
Documents -> Chunking -> Index -> Retrieval -> Context -> LLM -> Answer
```

نمونهٔ امروز تا مرحلهٔ ساخت `Context` پیش می‌رود و Citationها را حفظ می‌کند؛ بنابراین بدون کلید API قابل اجراست.

## 2. Chunking چرا مهم است؟

اگر Chunk خیلی بزرگ باشد، Context شلوغ و گران می‌شود. اگر خیلی کوچک باشد، معنی بین قطعات قطع می‌شود. `overlap` چند واژهٔ انتهای Chunk قبلی را در Chunk بعدی تکرار می‌کند تا پیوستگی بهتر حفظ شود.

```python
chunks = chunk_text(text, chunk_size=35, overlap=8)
```

اعداد مناسب به نوع سند، زبان، مدل Embedding و محدودیت Context وابسته‌اند و باید ارزیابی شوند.

## 3. Retrieval ساده و قابل فهم

نمونهٔ این درس برای هر Chunk مجموعه‌ای از Tokenها می‌سازد و بر اساس اشتراک واژه‌ها با Query امتیاز می‌دهد. این روش برای آموزش و Baseline مناسب است، اما جای Embedding یا موتور جست‌وجوی Production را نمی‌گیرد.

```python
score = len(query_tokens & chunk_tokens) / len(query_tokens)
```

سپس فقط `top_k` نتیجهٔ برتر که امتیاز مثبت دارند برگردانده می‌شوند.

## 4. Citation را از ابتدا حفظ کن

هر Chunk باید Metadata داشته باشد:

- `source_id`: شناسه یا نام سند
- `chunk_id`: شمارهٔ قطعه در سند
- در Production: URL، عنوان، نسخه و سطح دسترسی

خروجی Context:

```text
[source=crm-guide chunk=1]
هر تماس باید با شناسه کاربر ثبت شود...
```

مدل می‌تواند بر اساس این شناسه‌ها Citation بدهد. Citation واقعی زمانی معتبر است که برنامه بررسی کند شناسهٔ اعلام‌شده واقعاً در Context وجود داشته است.

نمونه شامل چند سند فارسی دربارهٔ CRM است، آن‌ها را Chunk می‌کند و برای یک سؤال نتایج مرتبط می‌سازد.

## 6. اتصال به LLM

پس از Retrieval، Prompt را با این قواعد بساز:

```text
فقط بر اساس Context پاسخ بده.
اگر پاسخ در Context نیست، صریح بگو اطلاعات کافی وجود ندارد.
بعد از هر ادعا شناسه منبع را مانند [source=...] درج کن.
```

خود Context را بین جداکننده‌های واضح قرار بده و محتوای سند را Instruction قابل اعتماد تلقی نکن؛ سند ممکن است Prompt Injection داشته باشد.

## نکات مهم

- Retrieval و Generation را جداگانه Log و ارزیابی کن.
- دسترسی کاربر را پیش از Retrieval اعمال کن؛ Citation جای Authorization را نمی‌گیرد.
- سؤال و سند فارسی به Normalization مناسب حروف `ی/ي` و `ک/ك` نیاز دارند.
- `top_k` زیاد همیشه بهتر نیست و می‌تواند Noise ایجاد کند.
- برای Production از Embedding، Hybrid Search یا Re-ranking متناسب با داده استفاده کن.

## اشتباهات رایج

- Chunk کردن فقط بر اساس تعداد Character و شکستن وسط جمله
- حذف Metadata و ناتوانی در ردیابی پاسخ
- فرستادن تمام اسناد به LLM بدون Retrieval
- قبول کردن دستورهای داخل سند به‌عنوان System Instruction
- ارزیابی فقط با چند سؤال ساده و خوش‌بینانه
