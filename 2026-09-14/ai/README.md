# Embedding و Semantic Search از صفر

## هدف

در پایان این آموزش می‌دانید Embedding چیست، شباهت Cosine چگونه محاسبه می‌شود و یک جست‌وجوی معنایی کوچک چگونه کار می‌کند.

## پیش‌نیاز

- Python 3.10 یا جدیدتر
- آشنایی مقدماتی با List و Dictionary
- نیاز نداشتن به API Key یا کتابخانه خارجی برای اجرای مثال

## Embedding چیست؟

Embedding نمایش عددی یک متن، تصویر یا شیء است. یک مدل Embedding متن را به برداری مانند زیر تبدیل می‌کند:

```text
"خطای ورود کاربر" → [0.12, -0.44, 0.81, ...]
```

بردارهایی که معنای نزدیک دارند معمولاً در فضای برداری به یکدیگر نزدیک‌ترند. در سیستم واقعی این بردار می‌تواند صدها یا هزاران بُعد داشته باشد.

## چرا جست‌وجوی کلمه‌ای کافی نیست؟

عبارت «مشکل لاگین» ممکن است سندی با عنوان «رفع خطای احراز هویت» را پیدا نکند، چون واژه‌ها متفاوت‌اند. جست‌وجوی معنایی تلاش می‌کند نزدیکی مفهوم را بسنجد.

## شباهت Cosine

برای دو بردار $A$ و $B$:

$$
\operatorname{cosine}(A,B)=\frac{A\cdot B}{\lVert A\rVert\lVert B\rVert}
$$

هرچه مقدار به `1` نزدیک‌تر باشد، جهت دو بردار شبیه‌تر است. برای بردار صفر نمی‌توان Cosine معتبر محاسبه کرد.

## Pipeline ساده

1. متن اسناد را آماده و پاک‌سازی کنید.
2. برای هر سند Embedding بسازید.
3. بردارها و Metadata را ذخیره کنید.
4. از Query نیز Embedding بسازید.
5. شباهت Query را با اسناد محاسبه کنید.
6. نتایج را بر اساس Score مرتب و Top-K را انتخاب کنید.

## مثال آموزشی بدون مدل خارجی

فایل [`examples/semantic_search.py`](./examples/semantic_search.py) از Hashing Vectorizer ساده استفاده می‌کند. این روش مدل زبانی واقعی نیست، اما Pipeline بردارسازی، شباهت و Ranking را شفاف نشان می‌دهد.

python examples/semantic_search.py "react api error"

## ارتباط با RAG

در RAG ابتدا اسناد مرتبط با همین روش بازیابی می‌شوند، سپس متن آن‌ها همراه سؤال به LLM داده می‌شود. بنابراین کیفیت Chunking، Embedding و Retrieval مستقیماً بر کیفیت پاسخ اثر می‌گذارد.

## نکات Production

- Embedding سند را یک بار بسازید و Cache کنید.
- مدل Embedding اسناد و Query باید یکسان باشد.
- متن‌های بزرگ را با هم‌پوشانی منطقی Chunk کنید.
- Metadata مانند `documentId`، عنوان و سطح دسترسی را همراه بردار نگه دارید.
- قبل از ارسال Context به LLM، مجوز دسترسی کاربر را بررسی کنید.
- کیفیت را با مجموعه Query و پاسخ مورد انتظار ارزیابی کنید، نه با چند مثال دستی.

## اشتباهات رایج

- مقایسه بردارهای ساخته‌شده با مدل‌های متفاوت
- تصور اینکه Score بالا همیشه به معنی پاسخ صحیح است
- نبود Filter دسترسی روی نتایج
- انتخاب Chunk بسیار بزرگ یا بسیار کوچک
- ارسال همه نتایج به LLM بدون محدودیت Token
- قراردادن اطلاعات حساس در Vector Store بدون سیاست امنیتی
